- **The debug `Tx::live_only` check names what the view built differently.** Its warning used to say only that the view built something else after a live-only handler. It now names the first element that differs and how: its layout rect, fill, border, opacity, radius, text, text colour or style, pills, rings, strikes or highlights, with both values when they're short (a rect, a colour, the first 40 characters of text), or an element added, removed or moved. For example: `rune: on_key called Tx::live_only, but the view built something else after it: text of "#0/heard" went from "1" to "2"`. It warns once per handler, element and property, and `Runtime::live_only_warnings` returns the warnings so a test can assert there are none. The check also no longer blames a live-only handler for state changed in the same frame by an `on_selection_change` handler (a text selection dragged across hover rows) or by a hover change a menu released. Release builds are unchanged.
